GOAL
Create ReplayRecorder.java — a buffer class with two responsibilities:
addSample(pose, gamepad1, gamepad2, dtMs), which serializes one sample
via ReplaySample.toBytes() and appends it to a preallocated byte buffer,
and writeHeader(sampleCount, mode), which produces the 16-byte header per
spec §4. No file I/O yet — that's Task 8 (saveToFile()).

EXISTING ARCHITECTURE

- ReplayFormatConstants.java has MAGIC*BYTES, VERSION, HEADER_SIZE,
  BASE_RECORD_SIZE, MODE_AUTONOMOUS, MODE_TELEOP, CHANNEL_TURRET, all
  BUTTON*\* masks.
- ReplaySample.java is the per-sample data holder with public
  x/y/headingDeg/dtMs fields, public gamepad1/gamepad2 (nested
  GamepadState: 15 booleans + 6 floats), and a working toBytes()
  producing a 72-byte little-endian record per spec §5.
- docs/replay-format-spec.md §4 gives the exact 16-byte header layout:
  offset 0x00 magic (4 bytes), 0x04 version uint16, 0x06 mode uint8,
  0x07 channels uint8, 0x08 sampleCount uint32, 0x0C recordSize uint16,
  0x0E reserved uint16 (must be 0x0000). §1.2 mandates little-endian for
  every multi-byte header field, same as records. §1.5 defines the file
  size equation the header's sampleCount/recordSize must satisfy
  (checked later, in Task 10's on-robot smoke test — not this task's
  job, but the header must be correct for that later check to pass).
- This task only produces channels=0 files (recordSize always 72,
  BASE_RECORD_SIZE) — optional channels are Phase 7 (Task 31), out of
  scope.
- docs/directory-structure.md §4.1 places this file at
  robot-module/src/main/java/org/firstinspires/ftc/teamcode/replay/ReplayRecorder.java

gamepad2, int dtMs)` — BUT since ReplaySample deliberately excludes

   ReplaySample's GamepadState booleans/floats from the two Gamepad

   certain of the exact Pose/Gamepad field names or accessor methods
   (e.g. is it pose.getX() or pose.x?), STOP and check FTC_SYNTAX.md
   first per AGENTS.md — do not guess. If FTC_SYNTAX.md doesn't have the
   pattern you need, stop and ask rather than inventing a plausible
   method name.
3. Provide `public byte[] writeHeader(int sampleCount, int mode)` that
   produces exactly 16 bytes per spec §4: magic bytes (from
   ReplayFormatConstants.MAGIC_BYTES), version (from
   ReplayFormatConstants.VERSION) as little-endian uint16, mode as a
   single byte (validate it's MODE_AUTONOMOUS or MODE_TELEOP — see
   Constraints), channels byte = 0x00 (this task never sets channel
   bits), sampleCount as little-endian uint32, recordSize as
   little-endian uint16 (always ReplayFormatConstants.BASE_RECORD_SIZE
   for this task), reserved = 0x0000.
4. Use the same explicit-little-endian ByteBuffer approach Task 5 used
   for toBytes() — do not rely on platform-default byte order here
   either.

CONSTRAINTS

- No file I/O anywhere in this class — no File, no FileOutputStream, no
  saveToFile() method. That is Task 8, a separate task per Plan.md and
  per AGENTS.md's "pure logic before hardware/UI/integration" rule.

  ReplayFormatConstants.MODE_AUTONOMOUS/MODE_TELEOP — throw

- Touch only this one new file — if you find you need to modify
