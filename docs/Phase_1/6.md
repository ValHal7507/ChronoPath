The test must:

1. Construct a ReplaySample and set: x=42.2417f, y=67.119f,
   headingDeg=-12.346f, dtMs=17; gamepad1.a=true,
   gamepad1.left_bumper=true (all other gamepad1 booleans false),
   gamepad1.left_stick_x=-0.50f, gamepad1.left_stick_y=0.75f,
   gamepad1.right_stick_x=0.00f, gamepad1.right_stick_y=-0.25f,
   gamepad1.left_trigger=0.00f, gamepad1.right_trigger=1.00f; gamepad2
   entirely default (all booleans false, all axes 0.0f) — per spec §8.2's
   raw input column. Re-verify these input values against §8.2 yourself
   rather than trusting this list, since transcription errors are exactly
   what this test exists to catch.
2. Call toBytes().
3. Assert the returned byte[] equals, byte-for-byte, the expected 72-byte
   sequence from spec §8.2:
   C3 F5 28 42 71 3D 86 42 9A 99 45 C1 11 00 00 00
   01 08 00 00 00 00 00 BF 00 00 40 3F 00 00 00 00
   00 00 80 BE 00 00 00 00 00 00 80 3F 00 00 00 00
   00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
   00 00 00 00 00 00 00 00
   Express the expected array as a hardcoded byte[] literal in the test
   (e.g. individual (byte) 0xC3, ... entries or a hex-string decoded at

   logic of your own; it must be copied, not recomputed.
4. Use a real assertion (assertArrayEquals or equivalent), not a manual
   loop with println — a mismatch must fail the test, not just print a

Also add at least one second test case asserting the returned array's
length equals 72 (ReplayFormatConstants.BASE_RECORD_SIZE) independent of
content, so a length regression fails clearly even if content happened to
coincidentally match elsewhere.
